## 3. MISTAKES AND FAILED APPROACHES

1. **Auto-Reseeding on Module Import**:
   - *What Happened*: Early version of `job_discovery.py` re-inserted 20 seed jobs with status `CONFIRMED_OPENING` whenever the module was imported.
   - *Why It Was Wrong*: Polluted database with fake confirmed openings and overwrote reality audit corrections.
   - *What We Learned & Fixed*: Removed automatic reseeding on import. Labeled initial records `SEEDED_NOT_VERIFIED`.
2. **Synthetic Requisition Slugs in Seed Data**:
   - *What Happened*: Seed jobs used synthetic URLs like `amazon.jobs/.../2648192` or `maersk.com/.../logistics-specialist-blr` which returned HTTP 404.
   - *Why It Was Wrong*: Caused candidate confusion and breached the supreme truth standard.
   - *What We Learned & Fixed*: Implemented `live_job_discovery.py` that queries genuine public APIs (SmartRecruiters, Lever, Greenhouse) for real vacancy IDs.
3. **Test Fixtures Elevating Application State**:
   - *What Happened*: An integration test generated a mock receipt and left `APP-JOB-AMZN-001` in `SUBMITTED` state.
   - *Why It Was Wrong*: Database falsely showed that an Amazon application was submitted.
   - *What We Learned & Fixed*: Created `ApplicationProofEngine` and `test_reality_audit.py` to continuously verify that no test receipt can mark an application as submitted.
